# Security policy

## Supported scope

Security reports are accepted for the current committed version of this portfolio, including:

- `index.html` and `404.html`;
- the local stylesheet and portrait;
- the static verification script;
- repository configuration or documentation that could cause unsafe publication; and
- the public GitHub Pages site at `https://saibshuvro.github.io/`.

The site is deployed. Availability reports are actionable when they identify behavior specific to this project; broad GitHub service incidents remain provider-owned.

The following are outside this project's control:

- vulnerabilities in GitHub, GitHub Pages, or GitHub Actions as platforms;
- vulnerabilities in LinkedIn, email providers, browsers, or other linked services;
- compromised visitor devices or networks; and
- social-media impersonation unrelated to this repository or site.

Vulnerabilities in GitHub products should follow [GitHub's coordinated disclosure process](https://bounty.github.com/). A report may still be sent here when a project-specific configuration is involved.

## Reporting

Email **saibsalehnabil@gmail.com** with a subject such as `Security report: portfolio`.

Include only the information needed to understand and reproduce the issue safely:

- the affected file, URL, or feature;
- a concise description and potential impact;
- reproducible steps using the least invasive method available;
- expected and observed behavior;
- relevant browser and operating-system versions; and
- sanitized logs, screenshots, or proof-of-concept material when useful.

Do not include credentials, access tokens, private keys, recovery codes, session cookies, unrelated personal data, or data obtained from other people. If a suspected secret is visible, identify its location and type without copying the value into the report. Ordinary email is not an end-to-end encrypted reporting channel.

Please avoid destructive testing, persistence, denial of service, automated high-volume scanning, privacy violations, or access beyond what is necessary to demonstrate the issue. Do not test GitHub infrastructure through this project.

## Response expectations

The reporting address is monitored on a best-effort basis. An acknowledgment is normally expected within five business days, but this is a target rather than a guaranteed service level. Triage, remediation, and disclosure timing depend on severity, reproducibility, and whether GitHub or another provider must act.

No bug bounty, payment, safe-harbor program, encrypted intake portal, or private vulnerability-reporting system is offered. Reporters should not assume that any of those programs exist.

## Disclosure

Allow a reasonable opportunity to investigate and address a confirmed project issue before public disclosure. The maintainer may publish a concise advisory or incident note when that materially helps users, while excluding exploit-enabling details, secrets, and unnecessary personal information.
